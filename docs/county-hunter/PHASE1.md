# NexusClaw County Hunter — Phase 1

## Scope

Phase 1 adds an isolated County Hunter workspace to the existing Next.js App Router application. It does not change the behavior of the existing agents, wallet, staking, contracts, leaderboard, token, or on-chain flows.

The workspace records investigative data and human decisions. It never buys property, places a bid, moves money, or represents that a title is clear.

## Runtime structure

```text
frontend/app/county-hunter/             protected workspace pages
frontend/app/api/county-hunter/         authenticated Route Handlers
frontend/features/county-hunter/        domain, validation, UI and Supabase adapters
frontend/tests/county-hunter/           unit and migration contract tests
supabase/migrations/                    additive county_hunter_* migrations
```

The repository has no shared worker, queue, cron framework, or job runner. Phase 1 therefore stores the discovery-run model but does not run crawling, downloads, parsing, monitoring, or reprocessing in page requests or in the browser.

## Feature flag

Set both values in the existing frontend environment only when the module is ready to be exposed:

```dotenv
COUNTY_HUNTER_ENABLED=true
NEXT_PUBLIC_COUNTY_HUNTER_ENABLED=true
```

When the flag is not exactly `true`:

- the public flag hides the TopNav item;
- the private flag makes `/county-hunter` and County Hunter APIs return 404.

## Shared authentication contract

No authentication or organization system was created. Phase 1.1 reuses the existing Supabase project through its SSR cookie-transported session and verifies the token server-side.

The authenticated user's Supabase `app_metadata` must contain:

```json
{
  "organization_id": "00000000-0000-0000-0000-000000000000"
}
```

Supported permissions:

- `county_hunter.view`
- `county_hunter.manage`
- `county_hunter.run_discovery`
- `county_hunter.approve_bid`
- `county_hunter.admin`

Permissions are stored in `county_hunter_memberships`, not in editable client state or JWT permission arrays. `county_hunter.admin` satisfies all County Hunter permission checks. Missing, expired, malformed, unassigned, or inactive sessions/memberships fail closed. See [PHASE1_1.md](./PHASE1_1.md).

The current NexusClaw frontend does not yet provide a Supabase sign-in flow. Phase 1 intentionally does not add one. The organization and permission claims must be assigned through the existing identity administration process before the UI can access data.

## Migrations

Apply in timestamp order to the existing Supabase project:

1. `202607230001_county_hunter_foundation.sql`
2. `202607230002_county_hunter_rls.sql`
3. `202607230003_county_hunter_seed_counties.sql`
4. `202607230004_county_hunter_auth_hardening.sql`

All new tables, functions, triggers, constraints, indexes, and policies use the `county_hunter_` prefix. Existing application tables are not changed.

The database enforces organization isolation through RLS and composite tenant foreign keys. Audit rows are append-only to authenticated application users and are generated by database triggers.

After migrations and claim assignment, an administrator can use County Hunter Settings to call the idempotent `county_hunter_seed_georgia` function. It creates:

- Georgia
- Fulton County
- Cobb County
- Chatham County
- Greene County
- Bryan County
- Camden County

No source URL, auction date, payment rule, location, or auction format is seeded. All counties start with `pending_manual_configuration`.

## Validation

Source URLs and all future outbound requests must:

- use HTTPS;
- contain no embedded credentials;
- not target localhost, loopback, link-local, private/reserved IPv4 or local/private IPv6 ranges;
- pass DNS resolution and every redirect through the server-only outbound URL guard.

No crawling or worker request is implemented in Phase 1/1.1.

## Phase 1 limitations

- Migrations were statically verified because this checkout has no Supabase CLI, Docker, or PostgreSQL client. Apply them to a local Supabase database before production.
- No current repository worker exists, so discovery execution is deferred.
- No county source URL has been verified or configured.
- No Supabase login UI was added.
- Settings persistence exists in the schema, but the Phase 1 UI exposes only safe county provisioning and authentication requirements.
- Valuation, risk scoring, shortlist operations, monitoring, bid preparation, and agent integration remain later phases.
